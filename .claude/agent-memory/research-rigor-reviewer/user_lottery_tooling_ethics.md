type: feedback

When this project's polished UX (Vietnamese-language dashboards, "Save to test/" buttons, ROI leaderboards, ticket-tracking CSVs) is the subject of review, name the gambling-tool concern explicitly in the review.

**Why:** A "research" disclaimer at the bottom of a readme does not neutralize a UI that lets a user generate, save, and track real-money tickets against future draws. The polish increases user confidence; the math has not changed. Failure to call this out is a silent endorsement.

**How to apply:** Always include a Benefit & Impact section that distinguishes intent (educational) from observed behavior (suggestion → save → track → repeat). Suggest concrete UX mitigations: visible per-ticket EV display, mandatory −EV warning before "Save", removal of "ROI %" framings that compound with single-shot variance, replacement of strategy "ranking" with a Monte-Carlo null distribution overlay.
